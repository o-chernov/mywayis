# MyWay — публичный сайт

Django-проект для апекс-домена `mywayis.com`: лендинг, регистрация, базовые
страницы и юридические документы. Личный кабинет живёт отдельно
(`app_frontend/`, React SPA на `app.mywayis.com`). API пишется заново и будет
жить в `backend/`.

**Сайт не хранит пользователей.** Единственный владелец этих данных — API.
Регистрация уходит туда HTTP-запросом; собственная база (SQLite) держит только
админку, тексты документов и заявки из формы обратной связи.

## Запуск

```bash
cd public_frontend
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
cp .env.example .env
.venv/Scripts/python manage.py migrate
.venv/Scripts/python manage.py compile_translations
.venv/Scripts/python manage.py createsuperuser
.venv/Scripts/python manage.py runserver 127.0.0.1:8000
```

Открыть <http://127.0.0.1:8000>, админка — `/admin/`.

| Команда | Что делает |
| --- | --- |
| `manage.py runserver` | Дев-сервер |
| `manage.py check` | Системные проверки, включая незаполненные реквизиты в документах |
| `manage.py check --settings=config.settings.prod --deploy` | Проверки для продакшена |
| `manage.py i18n_sync` | Обновляет `locale/en/…/django.po` по исходникам |
| `manage.py check_translations` | Падает, если есть непереведённые строки |
| `manage.py compile_translations` | Собирает `.mo` из `.po` |
| `manage.py collectstatic` | Статика для продакшена |

## Регистрация: контракт с API

Сайт отправляет запрос и разбирает ответ. Эндпоинта пока нет: API пишется
заново, а до тех пор форма работает в режиме-заглушке (см. ниже).

```http
POST {API_BASE_URL}/auth/register
Content-Type: application/json
X-Request-Id: <uuid4>

{
  "email":    "user@example.com",
  "username": "kirill_dev",
  "password": "<открытым текстом по HTTPS>",
  "locale":   "ru",
  "source":   "public_site"
}
```

Ограничения полей: `username` — до 64 символов, `email` — до 320. Форма проверяет
их до отправки, поэтому схема пользователей в API должна их повторить — иначе
сайт пропустит то, что API отклонит с `422`.

| Ответ | Тело | Поведение сайта |
| --- | --- | --- |
| `201` | `{"id","email","username","status","is_email_verified"}` | Страница «Аккаунт создан» |
| `409` | `{"detail":"email_taken"}` | Ошибка под полем email |
| `409` | `{"detail":"username_taken"}` | Ошибка под полем username |
| `422` | Стандартный формат FastAPI | Раскладывает по полям через `loc` |
| `429` | — | «Слишком много попыток» |
| `5xx`, таймаут | — | «Сервис временно недоступен» |

Таймаут 5 секунд, **ретраев нет**: POST не идемпотентен, повтор после таймаута
создал бы второго пользователя. Пароль никогда не логируется — за этим следит
фильтр `apps.core.logging_filters.ScrubSecretsFilter`.

Поля `status` и `is_email_verified` проставляет API. Подтверждение почты и
выбор специальности происходят в личном кабинете, а не здесь.

### Режим-заглушка

Пока эндпоинта нет, `REGISTRATION_BACKEND=stub` в `.env` включает заглушку:
форма работает целиком, помнит занятые логины и показывает оба конфликта.
Проверить можно на `taken@mywayis.com` и username `kirill_dev`.

В продакшене заглушка запрещена: `config/settings/prod.py` не даст приложению
стартовать с `REGISTRATION_BACKEND != http`.

## Что настраивается в админке

**Сайт → Настройки сайта** (одна запись):

- **Регистрация открыта** — тумблер закрывает приём новых пользователей
  мгновенно. `/registraciya/` начинает отдавать 503 с редактируемым текстом,
  все ссылки на регистрацию исчезают из шапки, подвала и страниц.
- **Юрисдикция документов** — `Россия` или `США`. Переключение полностью
  меняет состав раздела «Документы».
- Контакты, реквизиты, настройки аналитики.

**Документы → Юридические документы** — тексты в markdown с версией и датой
вступления в силу. Реквизиты подставляются плейсхолдерами `{{COMPANY_NAME}}`,
`{{COMPANY_INN}}`, `{{COMPANY_OGRN}}`, `{{COMPANY_ADDRESS}}`, `{{CONTACT_EMAIL}}`
— так они правятся в одном месте. `manage.py check` предупреждает, если
опубликованный документ содержит плейсхолдер, для которого поле не заполнено.

> Тексты из миграции — **рабочие черновики, не документы за подписью юриста**.
> Перед приёмом платежей их обязан вычитать профильный специалист, особенно
> оферту, политику возврата и обработку персональных данных.

## Языки

- Исходные строки в коде **на русском**: команда русскоязычная, шаблоны должны
  читаться без словаря. Переводится только каталог `locale/en`.
- Адреса тоже переводятся: `/tarify/` ↔ `/en/pricing/`. У русской версии
  префикса нет (`prefix_default_language=False`).
- `_("Email")` конфликтует с собственным каталогом Django («Адрес электронной
  почты»), поэтому такие строки размечены через `pgettext_lazy` с контекстом.
- Юридические документы **не переводятся автоматически**: они привязаны к
  юрисдикции, и русский текст в РФ является основным. Если английская версия
  документа не заведена, показывается основная для юрисдикции.
- Свободные поля настроек сайта (время ответа поддержки, наименование
  компании) — одноязычные: их набирает администратор, и каталог переводов
  на них не распространяется.

### Почему свои команды вместо makemessages

Штатные `makemessages` и `compilemessages` требуют бинарников GNU gettext,
которых на Windows обычно нет. `i18n_sync`, `check_translations` и
`compile_translations` делают то же самое на чистом Python
(`apps/core/i18n_tools.py`). Если gettext установлен, стандартные команды тоже
работают и дают тот же результат.

## Защита форм

Регистрация и контакты — публичные POST-эндпоинты:

- **honeypot** — скрытое поле; заполнено, значит бот. Ему показывается тот же
  успех, что и человеку, но ничего не отправляется: ответь мы ошибкой, бот
  понял бы, что попался, и подобрал обход;
- **время заполнения** — сабмит быстрее трёх секунд отбрасывается;
- **троттлинг** — 5 попыток за 10 минут на адрес, через стандартный кеш Django;
- **IP не хранится в открытом виде** — только соль плюс хеш, ради 152-ФЗ.

Капчи нет намеренно: на старте она отпугнёт больше живых людей, чем остановит
ботов. Место под неё предусмотрено.

## Оформление

`static/css/tokens.css` — копия `app_frontend/src/styles/tokens.css`. Сайт и
кабинет выглядят одним продуктом. **При изменении палитры обновляйте оба
файла**: сборщика ради одного файла в Django-проекте нет.

Тёмная тема по умолчанию, светлая переключателем. Инлайн-скрипт в `<head>`
ставит `data-theme` до первой отрисовки, иначе на тёмной теме мигает светлый фон.

В отличие от кабинета сайт **адаптивный**: лендинг открывают с телефона чаще,
чем с ноутбука.

## Структура

```
public_frontend/
├── config/settings/{base,dev,prod}.py
├── apps/
│   ├── core/      настройки сайта, антиспам, i18n-инструменты, sitemap, ошибки
│   ├── pages/     лендинг, возможности, тарифы, FAQ, о проекте
│   ├── accounts/  форма регистрации и клиент к API
│   ├── legal/     документы, юрисдикции, проверка реквизитов
│   └── contacts/  форма обратной связи
├── templates/     base.html, partials/, pages/, accounts/, legal/, errors/
├── static/css/    tokens.css (копия), site.css, landing.css
└── locale/en/     каталог переводов
```

## Чего здесь нет

Эндпоинта `/auth/register` и вообще любого кода в `backend/` — это отдельная
задача. Подтверждения почты и выбора специальности (они в кабинете). Блога,
вакансий, платёжной интеграции. Docker и CI — их нет ни в одном из трёх
проектов репозитория.
